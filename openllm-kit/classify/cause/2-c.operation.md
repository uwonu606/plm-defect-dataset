# 원인 축 2단계: `c.operation` 운용·구축 결함 아래 고르기

이 레코드는 1단계에서 `c.operation`로 정해졌다. 이제 그 아래 노드 하나를 고른다.

## 할 일

1. 아래 '고르는 규칙'이 있으면 그 순서를 따른다. 없으면 정의·포함 기준이 가장 잘 맞는 노드를 고른다.
2. 더 아래 노드(세분류)가 있으면 거기까지 내려간다. 세분류를 가를 근거가 없으면 그 위 노드에서 멈춘다.
3. 하위를 가를 근거가 없으면 `c.operation` 그대로 답한다.
4. 고른 노드의 포함 기준에 맞는 구절을 레코드 원문에서 그대로 복사해 evidence에 넣는다.

완료 기준: 레코드마다 `label`이 아래 목록 안의 값이고, `evidence`가 원문에 글자 그대로 있는 구절이다.

## 하위 노드

### `c.operation.procedure` 작업 절차 오류 (Procedure execution error)

- 표준 대응: NORS Procedural(Service Provider / System Vendor / Other Vendor)
- 정의: 작업 단계를 빠뜨리거나 순서를 바꾸거나, 잘못된 대상·명령으로 수행했거나, 정한 절차(MOP)·승인을 지키지 않았다.
- 포함: 업그레이드 뒤 이전 데이터 미정리, 필요한 파일 삭제, remove와 purge 혼동, 필요한 빌드 옵션 미사용, 오염된 빌드 환경, 필요한 구성요소를 배포·실행하지 않음, 잘못된 버전의 도구·링크를 씀, MOP 미준수 작업, 작업 대상 장비 착오, 승인 없는 작업.
- 이웃과 가르기: 남은 결과가 틀린 설정 값이면 c.content.config. 절차서 자체가 틀렸으면 c.content.doc이 주이고 이 노드는 보조.

### `c.operation.design` 구성·용량 설계 오류 (Configuration design or capacity planning error)

- 표준 대응: NORS Diversity Failure, Simplex Condition, Traffic/System Overload
- 정의: 망·시스템의 구성·배치·용량 산정이 부하·이중화·지원 조건에 맞지 않았다.
- 포함: 용량 산정 누락(초당 호수 등), 이중화·경로 분산 설계 오류, 단일 장애점 배치, 모든 VM을 한 장애 영역에 배치, 지원하지 않는 배치(같은 host에 함께 띄움), timing에 민감한 작업을 VM에서 실행, 사양을 넘는 host·bus 부하, 필요한 장비(외부 clock 등) 없이 구성, 부하에 맞춰 정해야 할 용량 parameter를 기본값으로 둠.
- 이웃과 가르기: 코드 안의 한도·자원 사용이 틀렸으면 c.code.resource. 정한 설계 값을 잘못 입력했으면 c.content.config.

## 출력

`label`은 `c.operation`, `c.operation.procedure`, `c.operation.design` 가운데 하나다. JSON 객체 하나만 낸다.

```json
{"results": [{"id": "<레코드 id>", "label": "<라벨>", "evidence": "<원문 구절>"}]}
```

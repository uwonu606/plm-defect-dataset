# 원인 축 2단계: `c.hw` 하드웨어 결함 아래 고르기

이 레코드는 1단계에서 `c.hw`로 정해졌다. 이제 그 아래 노드 하나를 고른다.

## 할 일

1. 아래 '고르는 규칙'이 있으면 그 순서를 따른다. 없으면 정의·포함 기준이 가장 잘 맞는 노드를 고른다.
2. 더 아래 노드(세분류)가 있으면 거기까지 내려간다. 세분류를 가를 근거가 없으면 그 위 노드에서 멈춘다.
3. 하위를 가를 근거가 없으면 `c.hw` 그대로 답한다.
4. 고른 노드의 포함 기준에 맞는 구절을 레코드 원문에서 그대로 복사해 evidence에 넣는다.

완료 기준: 레코드마다 `label`이 아래 목록 안의 값이고, `evidence`가 원문에 글자 그대로 있는 구절이다.

## 하위 노드

### `c.hw.design` HW 설계 결함 (Hardware design defect)

- 표준 대응: NORS Design-Hardware
- 정의: 회로, 부품 선정, 열 설계, FPGA 논리·timing 같은 HW 설계가 요구와 달라서 같은 설계의 모든 개체에 나타난다.
- 포함: 회로 오류, 부품 정격 부족, 열 설계 부족, FPGA bitstream timing 위반, 신호 무결성 문제, 설계 단계의 부품 호환성 문제.
- 이웃과 가르기: 특정 개체·lot에만 나타나는 고장·제조 불량은 c.hw.failure. FW 코드면 c.code.

### `c.hw.failure` HW 고장·제조 불량 (Hardware failure or manufacturing defect)

- 표준 대응: NORS Hardware Failure; Avizienis physical fault(internal)
- 정의: 개별 부품·장비가 고장 났거나 열화·마모됐거나 제조 불량이라서 특정 개체·lot에 나타난다.
- 포함: fan 베어링 마모, DRAM·부품 제조 불량, 광 모듈 고장, port·connector 불량, cable 불량, 경년 열화, 보드 고장.
- 이웃과 가르기: 같은 설계의 모든 개체에 나타나면 c.hw.design. 외부 사건(정전, 낙뢰, 침수, 절단)이 HW를 망가뜨렸으면 c.env가 주. lot 단위인지는 반영 범위 facet.

## 출력

`label`은 `c.hw`, `c.hw.design`, `c.hw.failure` 가운데 하나다. JSON 객체 하나만 낸다.

```json
{"results": [{"id": "<레코드 id>", "label": "<라벨>", "evidence": "<원문 구절>"}]}
```

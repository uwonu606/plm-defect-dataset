# 원인 축 2단계: `c.code` 소프트웨어 결함 아래 고르기

이 레코드는 1단계에서 `c.code`로 정해졌다. 이제 그 아래 노드 하나를 고른다.

## 할 일

1. 아래 '고르는 규칙'이 있으면 그 순서를 따른다. 없으면 정의·포함 기준이 가장 잘 맞는 노드를 고른다.
2. 더 아래 노드(세분류)가 있으면 거기까지 내려간다. 세분류를 가를 근거가 없으면 그 위 노드에서 멈춘다.
3. 하위를 가를 근거가 없으면 `c.code` 그대로 답한다.
4. 고른 노드의 포함 기준에 맞는 구절을 레코드 원문에서 그대로 복사해 evidence에 넣는다.

완료 기준: 레코드마다 `label`이 아래 목록 안의 값이고, `evidence`가 원문에 글자 그대로 있는 구절이다.

## 고르는 규칙

L2는 고친 내용(코드 변경이 무엇을 바꿨나)으로 고른다. 해결 서술이 없으면 원인 서술이 짚은 잘못으로 고른다. 둘 이상 맞으면 이 순서에서 먼저 걸리는 것을 고른다: c.code.concurrency(실행 순서·동기화를 통제하게 고침) → c.code.resource(자원 수량·한도·해제·효율을 고침) → c.code.state(객체를 만들거나 지우게, 또는 상태 값을 설정·갱신·복원하게 고침) → c.code.guard(바깥에서 온 값·요청을 검사하거나 실패 결과를 처리하게 고침. 검사를 완화하거나 다른 계층으로 옮긴 것도 든다) → c.code.encoding(encode·decode·직렬화 코드나 메시지 형식 정의를 고침) → c.code.interface(우리 코드가 다른 구성요소를 호출하는 방식·인자·결과 해석을 고침) → c.code.logic(그 밖의 조건·분기·계산·값·빠진 처리).

## 하위 노드

### `c.code.logic` 처리 논리 오류 (Processing logic error)

- 표준 대응: ODC Defect Type Algorithm/Method, Assignment/Initialization, Function/Class/Object, Checking(조건); ODC Qualifier(Missing/Incorrect/Extraneous)는 qualifier facet; IEEE 1044 Type Logic·Data
- 정의: 입력·상태·상대가 정상인데 코드의 조건·분기·참조 대상·계산이 틀렸거나, 정상 범위의 경우나 약속한 기능을 다루지 않아 결과가 틀렸다.
- 포함: 반대·누락된 조건, 다른 필드와의 비교, 오타 변수·이름, 엉뚱한 변수·ID 선택, 유일하지 않은 식별 key, 너무 넓은 query 조건, 특정 설정 조합·optional 요소·추가 인스턴스에 대한 분기 없음, 조건을 보지 않고 늘 같은 값·동작을 씀(하드코딩), 노출한 method 미구현, 규격이 요구한 절차 단계·필수 요소·필드 값·응답 코드 누락(요구 출처 facet=표준), 잘못된 상수·literal, off-by-one, 산술·비트·단위 환산·자료형 변환 오류, 내부의 두 표현(enum, 구조체) 사이 값 대응 오류, buffer offset 계산 오류. 빠진 것인지 틀린 것인지는 qualifier facet(누락/오류/불필요)에 적는다. 우리 코드 안에 빠진 정의·옵션·등록·처리를 더한 것도 여기다(다른 구성요소가 그것을 찾다 실패했어도).
- 이웃과 가르기: c.code의 L2 판정 순서에서 앞 노드가 맞으면 그 노드다. 이 노드는 남는 것을 받는다. 바깥에서 온 값을 거르지 않았거나 실패 결과를 처리하지 않았으면 c.code.guard. 객체의 상태 값이나 생성·정리 시점이 틀렸으면 c.code.state. 원인 서술이 상대 구성요소가 무엇을 받는지·돌려주는지·어떻게 동작하는지를 근거로 들면 c.code.interface. 바깥으로 내보내거나 받는 메시지·데이터의 표현 규칙(인코딩·직렬화)이 틀렸으면 c.code.encoding.

### `c.code.guard` 검사·오류 처리 결함 (Checking and error-handling defect)

- 표준 대응: ODC Defect Type Checking; NORS Design-Software Inadequate Defensive Checks, Ineffective Fault Recovery or Re-initialization Action; CWE-20·CWE-284·CWE-754 계열(CWE 원문 미대조)
- 정의: 들어오는 값과 요청을 거르는 검사, 또는 실패한 호출의 뒤처리가 빠졌거나 틀렸다.
- 포함: 바깥 입력 검증 누락, 인가·출처 검증 누락, 실패 결과 미검사, 예외 삼킴·잘못된 오류 변환, 회복 가능한 실패를 assert로 끝냄.
- 이웃과 가르기: 정상 범위 입력을 틀리게 처리했으면 c.code.logic. 고정 한도를 넘어 자원이 고갈된 것이 핵심이면 c.code.resource.

### └ `c.code.guard.input` 입력 검증 누락·오류 (Missing or wrong input validation)

- 표준 대응: ODC Checking; NORS Inadequate Defensive Checks; CWE-20 Improper Input Validation(CWE 원문 미대조)
- 정의: 신뢰 경계 밖(사용자, 상대 메시지, 파일, 설정 값, 외부 응답)에서 온 값의 형식·범위·길이·중복·필수 요소를 검사·거부하지 않았거나 검사 기준이 틀렸다.
- 포함: 길이·index·범위·개수 상한 검사 누락, 바깥 메시지에 필수 요소가 없는데 있다고 가정하고 역참조(nil·NULL 역참조 포함), 허용 밖 enum·형식 통과, 중복 요청 미거부, 외부 입력을 assert로 단정, 검사가 너무 엄격해 유효한 값을 막음, 설정 값 validation 누락. 검사 기준을 고쳐 유효한 값을 막지 않게 하거나 검사를 다른 계층으로 옮긴 것도 여기다.
- 이웃과 가르기: nil·NULL이 우리 쪽 조회·호출의 실패 결과에서 왔으면 c.code.guard.error. 바깥 값을 거르지 않은 데다 그 실패를 assert·abort로 끝냈으면 이 노드가 주 라벨, c.code.guard.error가 보조 라벨이다. 요청자의 권한·출처·노출 범위를 검사하지 않았으면 c.code.guard.access. 값이 내부에서 만들어졌으면 c.code.logic.

### └ `c.code.guard.access` 인가·출처 검증 누락 (Missing authorization or origin check)

- 표준 대응: CWE-284 Improper Access Control, CWE-862 Missing Authorization, CWE-863 Incorrect Authorization(CWE 원문 미대조, L3 깊이 조건의 표준 대응 면제 근거); X.736 security alarm 계열(미확인)
- 정의: 요청자의 권한, 요청이 온 출처, 서비스가 노출되는 범위를 확인하지 않았거나 틀린 대상으로 확인했다.
- 포함: 인가 middleware 누락, 권한 검사 target·action 이름 오류, redirect·href host 미검증, 의도보다 넓은 주소에서 listen, 다른 도메인·망 식별자 요청 수용, 기본 token으로 인증 우회.
- 이웃과 가르기: 권한과 무관한 값 형식·범위 검사면 c.code.guard.input. 제품이 내보낸 권한 정책 파일의 규칙이 틀렸으면 c.content.config. 규격이 요구한 인가 단계가 빠졌어도 여기다(요구 출처 facet=표준).

### └ `c.code.guard.error` 실패 결과·예외 처리 결함 (Failure-result or exception handling defect)

- 표준 대응: ODC Checking(오류 경로); NORS Ineffective Fault Recovery or Re-initialization Action; CWE-252·CWE-754·CWE-755 계열(CWE 원문 미대조)
- 정의: 실패할 수 있는 호출의 결과를 검사하지 않았거나, 실패·예외 뒤의 경로(오류 응답, 전파, 재시도, 기록)를 잘못 처리했다.
- 포함: 조회·할당 결과 NULL·zero value 미검사(이미 지운 대상 조회 포함), parse 실패 뒤 계속 진행, 오류 응답 대신 assert, 예외 삼킴·기록 누락, 원래 오류를 덮음, 오류 코드를 다른 코드로 바꿔 전달, 없는 대상 조회에 맞는 오류 대신 내부 오류 응답, 정상 상황을 ERROR로 기록.
- 이웃과 가르기: nil·NULL이 바깥 메시지에 요소가 빠져서 생겼으면 c.code.guard.input. 실패가 자원 고갈 때문이고 한도 설계가 핵심이면 c.code.resource.

### `c.code.state` 상태·수명주기 관리 오류 (State and lifecycle management error)

- 표준 대응: ODC Assignment/Initialization 일부; 기존 cause_class 상태 관리
- 정의: 세션·컨텍스트·객체의 생성·정리 시점이나 상태 값의 초기화·전이·복원이 틀려, 처리 시점의 상태가 코드의 가정과 달랐다.
- 포함: 정리 누락·과잉·순서 오류, 이미 지워졌거나 해제됐거나 아직 없는 대상 참조(use-after-free, double free 포함), 초기화 누락·중복, 상태 변화 미반영, 실패·재시작 뒤 복원 실패. L3: 고친 것이 객체·항목·컨텍스트를 만들거나 지우는 일(또는 지워진 대상의 참조를 막는 일)이면 c.code.state.lifecycle, 이미 있는 대상의 값을 설정·갱신·복원하는 일이면 c.code.state.transition. cache 항목을 지우는 것은 lifecycle이다.
- 이웃과 가르기: 둘 이상의 실행 흐름이 겹쳐야 재현되면 c.code.concurrency. 메모리·핸들·pool 같은 시스템 자원의 수량 문제면 c.code.resource. 규격이 정한 상태 전이를 어겼어도 여기다(요구 출처 facet=표준).

### └ `c.code.state.lifecycle` 생성·정리 시점 오류 (Create or cleanup timing error)

- 표준 대응: ODC Algorithm/Method(근사); CWE-416 Use After Free·CWE-415 Double Free(CWE 원문 미대조)
- 정의: 객체·컨텍스트·장치·메모리를 만들거나 지우는 일을 빠뜨렸거나 너무 이르게·두 번·잘못된 순서로 했거나, 이미 지워졌거나 아직 만들어지지 않은 대상을 참조했다.
- 포함: 삭제 때 장치·status 미정리, signal 종료 때 정리 미실행, 의존 대상 확인 없이 제거, release 뒤 도착한 메시지 처리, 미완성 컨텍스트로 송신, 정리가 idempotent하지 않음, 해제된 buffer·객체를 계속 가리킴(use-after-free), 이중 해제, 소유하지 않은 pointer 해제.
- 이웃과 가르기: 대상은 제대로 있는데 그 상태 값이 초기화·갱신·복원되지 않았으면 c.code.state.transition. 정리 누락으로 메모리·핸들·FD가 쌓여 고갈되는 것이 핵심이면 c.code.resource. 지워진 대상을 조회한 결과를 검사하지 않은 것이 핵심이면 c.code.guard.error.

### └ `c.code.state.transition` 상태 초기화·전이·복원 오류 (State initialization, transition or restore error)

- 표준 대응: ODC Assignment/Initialization
- 정의: 상태 값이 초기화되지 않았거나, 상태 변화(역할 전환, 비활성화, 삭제, 재시작)에 맞춰 바뀌지 않았거나, 실패 뒤 원래대로 되돌려지지 않았다.
- 포함: 초기값 없는 속성, 특정 실행 모드에서 건너뛴 init, 생성자 부작용으로 생긴 중복 초기화, HA 역할 전환 미반영, 비활성 항목 계속 사용, rollback·commit 누락, 재시작 뒤 table 미복원, 상태 공유 범위 오류(class 변수).
- 이웃과 가르기: 객체의 존재 자체(생성·정리·이미 지워진 대상 참조)가 문제면 c.code.state.lifecycle. 상태는 맞는데 그 상태를 보고 내린 판단이 틀렸으면 c.code.logic.

### `c.code.concurrency` 동시성·실행 순서 오류 (Concurrency or ordering error)

- 표준 대응: ODC Defect Type Timing/Serialization; 기존 cause_class 동시성
- 정의: 둘 이상의 실행 주체(thread·process·agent·node)나 비동기 이벤트가 겹치는 순서를 코드가 통제하지 않아 경합·교착이 생겼다.
- 포함: race condition, TOCTOU, deadlock, 공유 자료구조 보호 누락, 비동기 메시지·패킷 도착 순서 의존, 두 이벤트 원천의 중복 처리, 일괄 적용과 개별 적용의 순서 뒤바뀜.
- 이웃과 가르기: 한 실행 흐름 안에서 정리·전이 순서가 틀렸으면 c.code.state. 실시간 경로의 blocking·지연이면 c.code.resource. 병렬 시험끼리 간섭했으면 c.test.

### `c.code.resource` 자원·성능 결함 (Resource or performance defect)

- 표준 대응: X.733 probableCause Storage Capacity Problem·Out Of CPU Cycles(근사); NORS Traffic/System Overload(근사)
- 정의: 메모리·핸들·pool·CPU·시간 같은 자원의 수량을 새게 하거나 한도를 넘기거나 비효율적으로 써서 실패·지연이 생겼다.
- 포함: 누수(예외 경로 메모리, goroutine·FD), reference count 불일치, 고정 크기 pool·배열 고갈, 상한 없는 할당·저장, 부하에서 queue·memory 고갈, 항목마다 DB 조회, 불필요한 복사, 비효율 query, 실시간 경로의 blocking·mutex, backoff 없는 재시도·full sync 폭주, timer·timeout 값 설계 오류.
- 이웃과 가르기: 해제된 메모리를 쓰거나 두 번 해제했으면 수량이 아니라 존재 시점 문제라 c.code.state.lifecycle. 한도 값이 제공 설정·운용 설정 값이면 c.content.config. 한도가 설계상 의도라고 판정됐으면 _na. 외부 입력 길이를 검사하지 않아 배열을 넘었으면 c.code.guard.input. 두 흐름의 순서가 문제면 c.code.concurrency. 코드가 아니라 설비 수량·망 용량 계획이 모자라면 c.operation.design.

### `c.code.interface` 구성요소 계약 불일치 (Component contract mismatch)

- 표준 대응: ODC Defect Type Interface/O-O Messages, Relationship(근사); IEEE 1044 Type Interface
- 정의: 코드가 함께 동작하는 다른 구성요소(내부 module, library, DB 엔진, OS 명령, 상대 시스템·장비)의 계약(받는 인자·형식, 전제조건, 반환값, 동작, 지원 범위)을 잘못 가정했고, 상대는 바뀌지 않았다.
- 포함: 고친 내용이 우리 코드가 다른 구성요소를 호출·사용·해석하는 방식(인자, 호출 순서·조건, 반환값·출력 해석, 상대 변종 처리)을 바꿨다. 원인 서술이 상대가 무엇을 받는지·돌려주는지·어떻게 동작하는지를 근거로 든다. 상대가 받지 않는 인자·형식을 넘김, 필요한 context·decorator 없이 호출, 공통부 변경이 plugin에 미반영, import·등록 부작용 가정, 명령 종료 코드·출력 형식 오해, 상대의 변종(내장 module, 다른 배포판, 설정에 따라 달라지는 출력·동작)을 처리하지 못함, 라이브러리 option·flag의 의미 오해, 특정 DB 엔진·실행 모드만 가정, 상대 시스템의 이름 규칙·선택 기능 지원·배치 구조(중계 노드)를 잘못 가정. 계약을 정한 것이 표준 규격인지 상대 구현인지는 요구 출처 facet에 적는다.
- 이웃과 가르기: 원인 서술이 우리 쪽에서 엉뚱한 변수·ID를 넘긴 것만 짚으면 c.code.logic. 상대가 의도적으로 바뀌었으면(새 버전·기본값 변경) c.supply.dependency. 상대 SW 자체의 결함이면 그 메커니즘 노드(원인 소재 facet=공급사·OSS 또는 제3자). 우리가 해야 할 절차 단계·필수 요소를 빠뜨렸으면 c.code.logic. 메시지 인코딩 규칙을 어겼으면 c.code.encoding. 우리 코드 안에 빠진 정의·옵션·등록을 더했으면 c.code.logic.

### `c.code.encoding` 표현·인코딩 오류 (Encoding or serialization error)

- 표준 대응: IEEE 1044 Type Data(일부)
- 정의: 메시지·IE·필드·데이터를 정해진 표현 규칙(규격, 공개 형식, 상대와 합의한 형식)과 다르게 쓰거나 읽었다.
- 포함: 고친 것이 encode·decode·직렬화 코드나 메시지·데이터 형식 정의다. deserializer·decoder 오류, 감싸야 할 구분자 누락(IPv6 대괄호, {}), padding·presence bit 배치 계산, 필드 type 폭이 규격 범위보다 좁음, 잘못된 PDU type 설정, optional IE·확장 값 encode·decode 미지원, 필드·배열 이름 표기 오류.
- 이웃과 가르기: 형식은 맞는데 절차·필수 요소·값이 요구와 다르면 c.code.logic(요구 출처 facet=표준). 내부 구조체·enum 사이 값 대응이면 c.code.logic. decode 함수에 엉뚱한 인자를 넘겼으면 c.code.logic. 메시지에 넣는 값 자체(엉뚱한 변수, 타입 변환 누락)를 고쳤으면 c.code.logic.

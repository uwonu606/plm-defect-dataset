# 원인 축 2단계: `c.content` 설정·데이터·문서 내용 결함 아래 고르기

이 레코드는 1단계에서 `c.content`로 정해졌다. 이제 그 아래 노드 하나를 고른다.

## 할 일

1. 아래 '고르는 규칙'이 있으면 그 순서를 따른다. 없으면 정의·포함 기준이 가장 잘 맞는 노드를 고른다.
2. 더 아래 노드(세분류)가 있으면 거기까지 내려간다. 세분류를 가를 근거가 없으면 그 위 노드에서 멈춘다.
3. 하위를 가를 근거가 없으면 `c.content` 그대로 답한다.
4. 고른 노드의 포함 기준에 맞는 구절을 레코드 원문에서 그대로 복사해 evidence에 넣는다.

완료 기준: 레코드마다 `label`이 아래 목록 안의 값이고, `evidence`가 원문에 글자 그대로 있는 구절이다.

## 하위 노드

### `c.content.config` 설정·데이터 값 오류 (Configuration or data value error)

- 표준 대응: NORS Faulty Software Translations; NORS Procedural(설정 입력); X.733 configuration 계열 probableCause(미확인)
- 정의: 제품 기본값·예제 설정·정책 파일·운영 파일, 또는 운용자·사용자가 넣은 설정 값·가입자 데이터·상대 장비 설정이 틀렸거나 빠졌거나 서로 맞지 않는다.
- 포함: 잘못된 기본 port·URL, 자원·HW와 맞지 않는 기본값, policy 규칙 누락·과잉 제한, 같은 항목 중복 정의, logrotate 같은 운영 파일 누락, 주소 중복, 필수 설정 키 누락, 설정 파일 형식 오류, 남아 있던 이전 설정, 환경 변수가 설정을 덮어씀, 옵션 의미 오해로 넣은 값, host 방화벽·OS 설정이 traffic·기능을 막음, interface를 올리지 않음, 가입자 key·SIM 값 오류, 단말의 기능 설정, 상대 장비와 맞지 않는 설정(slice·TAI·주소).
- 이웃과 가르기: 문서의 설명·예시가 틀렸으면 c.content.doc. 권한 검사 코드가 틀렸으면 c.code.guard.access. 설정 값이 아니라 구성·용량 설계가 부하·이중화에 맞지 않으면 c.operation.design.

### `c.content.doc` 문서·안내 오류 (Documentation error)

- 표준 대응: ODC Target=Information Development; IEEE 1044 Type Description(2차 출처); NORS Procedural Documentation/Procedures Out of Date(근사)
- 정의: 매뉴얼, API reference, README, 튜토리얼, 작업 절차서(MOP)가 실제 동작과 다르거나 틀렸거나 빠졌다.
- 포함: parameter 누락·위치 오표기, 틀린 예시 값·ID·명령, 낡은 link, 배포마다 다른 값을 고정값처럼 안내, 코드 변경 뒤 남은 옛 옵션. 작업 절차서의 단계 누락·오기.
- 이웃과 가르기: 문서는 맞는데 코드가 문서와 다르게 동작하면 c.code. 제공 설정 파일의 값이 틀렸으면 c.content.config. 문서 추가·개선 요청(기능 요청)은 _na.

## 출력

`label`은 `c.content`, `c.content.config`, `c.content.doc` 가운데 하나다. JSON 객체 하나만 낸다.

```json
{"results": [{"id": "<레코드 id>", "label": "<라벨>", "evidence": "<원문 구절>"}]}
```

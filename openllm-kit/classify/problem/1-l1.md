# 문제점 축 1단계: 대분류 고르기

축의 질문은 "관찰된 현상·증상. 무엇이 어떻게 잘못 보였나."이다. 근거는 레코드 유형, 제목, 현상에서만 찾는다.

## 할 일

1. 레코드를 읽는다.
2. 아래 질문을 Q1부터 차례로 묻고, 처음 "예"가 나온 질문에서 멈춘다. 그 질문의 라벨이 답이다.
3. 멈춘 질문에 "예"라고 답하게 한 구절을 레코드 원문에서 그대로 복사해 evidence에 넣는다.

Q1~Q9는 실행에서 관찰됐거나 코드 검토로 예상된 잘못된 동작을 묻는다. 개선·기능 요청이 바라는 상태(더 빠르게, 더 적게, 새로 지원)는 관찰된 잘못이 아니므로 Q10이다. 증상이 여럿이면 먼저 "예"가 나온 쪽이 주 라벨이다. 질문 순서가 서비스 영향 순서다. 라벨이 둘 적힌 질문은 그 가운데 맞는 하나를 답한다.

완료 기준: 레코드마다 `label`이 아래 라벨 목록 안의 값이고, `stop`이 멈춘 질문 번호(어느 질문에도 "예"가 없어 마지막 안내로 끝났으면 0)이고, `evidence`가 원문에 글자 그대로 있는 구절이다.

## 질문

| Q | 질문 | "예"이면 |
|---|---|---|
| 1 | 이미 동작하던 process·서비스가 예기치 않게 끝났거나(crash, abort, assert, panic, 스스로 재시작) 응답 없이 멈췄나? | `p.halt` |
| 2 | 설치하거나 기동·초기화하는 단계가 끝나지 않았나? | `p.stage.install` 또는 `p.stage.startup` |
| 3 | 단말·가입자·peer 노드·관리 시스템 사이의 접속 수립, 연결 유지, 데이터 전달이 실패하거나 나빠졌나? | `p.conn` (하위: 접속·세션 수립 실패, 연결 끊김·데이터 전달 실패) |
| 4 | 인증·권한·격리·무결성 같은 보안 통제가 적용되지 않아, 허용되면 안 되는 접근·조작·노출이 가능한가? | `p.sec` |
| 5 | process는 살아 있는데 요청·작업이 오류로 끝나거나 결과·상태가 기대·규격·운영자 설정과 다른가? | `p.func` (하위: 요청·작업 실패, 잘못된 결과·상태) |
| 6 | 결과는 맞지만 느리거나, 처리량이 모자라거나, 자원을 필요 이상 쓰거나 계속 늘리나? | `p.perf` |
| 7 | 서비스 증상 없이 장비·부품·설비·자원 상태가 정상 범위를 벗어났거나 곧 벗어난다고 보고됐나? | `p.state` (하위: 장비·부품 고장, 환경·설비 조건 이상) |
| 8 | 제품 동작은 맞고 문서·예시 설정·로그·경고·알람·화면 문구가 틀리거나 빠지거나 헷갈리게 하나? | `p.info` (하위: 문서 오류·누락, 로그·알람·화면 문구 이상) |
| 9 | 빌드하거나 시험하는 단계(compile, CI job, 시험 실행)가 실패했나? | `p.stage.build` 또는 `p.stage.test` |
| 10 | 있는 기능의 오동작이 아니라, 없는 기능·지원이나 코드·시험·절차 보강이 요청 배경인가? | `p.gap` (하위: 기능·지원 부재, 코드·시험·절차 보강) |

어느 질문에도 "예"가 없으면: 기술 증상을 판정할 내용이 없으면 `_none`, 현상도 부족함도 없는 작업 기록·문의면 `_na`, 현상은 있는데 맞는 곳이 없으면 `_other`.

## 대분류 정의

- `p.halt` 비정상 종료·멈춤 (Abnormal termination or hang): 이미 동작하던 process·서비스가 예기치 않게 끝나거나 스스로 재시작하거나, 살아 있지만 더 진행하지 못하고 응답하지 않는다.
- `p.stage` 빌드·시험·설치·기동 실패 (Build, test, install or startup failure): 구성 요소를 빌드하고, 시험하고, 설치하고, 기동하는 단계 작업이 끝나지 않아 다음 단계(시험 통과, 운용 상태)에 이르지 못한다.
- `p.conn` 접속·연결 이상 (Connectivity problem): 단말·가입자·peer 노드 사이, 또는 관리 시스템과 장비 사이의 접속 수립, 연결 유지, 데이터 전달이 실패하거나 나빠진다.
- `p.func` 기능 오동작 (Functional misbehavior): process는 살아 있고 응답하지만, 요청·작업이 오류로 끝나거나 결과·상태가 기대·규격·운영자 설정과 다르다.
- `p.perf` 성능·자원 이상 (Performance or resource problem): 결과는 맞지만 처리·응답·복구가 오래 걸리거나, 처리량이 기준에 못 미치거나, 자원을 필요 이상 쓰거나 계속 늘린다.
- `p.sec` 보안 통제 실패 (Security control failure): 인증·권한·격리·무결성·기밀성 같은 보안 통제가 적용되지 않아, 허용되면 안 되는 접근·조작·노출이 가능하다.
- `p.info` 문서·출력 문구 이상 (Documentation or message issue): 제품 동작은 맞지만 사람이 읽는 정보(문서, 예시 설정, 로그, 경고, 알람, 오류 문구, 화면 표시·이름)가 틀리거나, 빠지거나, 지나치거나, 헷갈리게 한다.
- `p.state` 구성요소·설비 상태 이상 (Equipment or facility condition): 서비스 증상이 아직 없거나 적히지 않은 채, 장비·부품·설비·자원의 상태가 정상 범위를 벗어났거나 곧 벗어난다고 보고된다.
- `p.gap` 기능·개선 필요 (Capability or improvement need): 있는 기능의 오동작이 아니라, 필요한 기능·지원이 없거나 코드·시험·절차를 보강해야 하는 상태가 요청 배경으로 적혔다.

## 특수 코드

- `_none`: 기술 증상을 판정할 내용이 원문에 없다.
- `_na`: 현상도 부족함도 적히지 않은 순수 작업 기록이나 문의다.
- `_other`: 현상은 적혀 있지만 위 어느 노드에도 맞지 않는다.

## 출력

JSON 객체 하나만 낸다.

```json
{"results": [{"id": "<레코드 id>", "stop": 3, "label": "<라벨>", "evidence": "<원문 구절>"}]}
```

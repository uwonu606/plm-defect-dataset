# 문제점 축 2단계: `p.conn` 접속·연결 이상 아래 고르기

이 레코드는 1단계에서 `p.conn`로 정해졌다. 이제 그 아래 노드 하나를 고른다.

## 할 일

1. 아래 '고르는 규칙'이 있으면 그 순서를 따른다. 없으면 정의·포함 기준이 가장 잘 맞는 노드를 고른다.
2. 더 아래 노드(세분류)가 있으면 거기까지 내려간다. 세분류를 가를 근거가 없으면 그 위 노드에서 멈춘다.
3. 하위를 가를 근거가 없으면 `p.conn` 그대로 답한다.
4. 고른 노드의 포함 기준에 맞는 구절을 레코드 원문에서 그대로 복사해 evidence에 넣는다.

완료 기준: 레코드마다 `label`이 아래 목록 안의 값이고, `evidence`가 원문에 글자 그대로 있는 구절이다.

## 하위 노드

### `p.conn.setup` 접속·세션 수립 실패 (Access or session setup failure)

- 표준 대응: 3GPP TS 28.554 Accessibility; IANAItuProbableCause callEstablishmentError(503) (IANAItuProbableCause 이름·번호는 RFC 3877 MIB 원문과 대조하지 않았다)
- 정의: 단말·peer가 접속·등록·세션·link를 맺으려다 거절되거나, 응답을 받지 못하거나, 끝내지 못한다.
- 포함: attach·registration·service request·PDU session·bearer 수립 reject·실패, random access 미완료, cell 탐색·camp 실패, peer association·제어 link(SCTP, Diameter, TLS 등) 수립 실패, 수립 중 상대가 끊음, 인증 절차 실패.
- 이웃과 가르기: 수립 절차(등록·세션·link 수립)가 끝난 뒤 끊기거나, 수립은 됐는데 데이터가 안 흐르면 p.conn.delivery. 수립 절차가 끝나기 전에 거절·해제되면 여기다. 운영자의 관리 API·CLI 요청 실패는 p.func.fail. 메시지 IE 이상이 거절을 낳았으면 주 라벨은 여기, p.func.wrong은 보조.

### `p.conn.delivery` 연결 끊김·데이터 전달 실패 (Connection loss or data delivery failure)

- 표준 대응: 3GPP TS 28.554 Retainability·Integrity; IANAItuProbableCause communicationsSubsystemFailure(505)·transmissionError(10)·degradedSignal(3) (IANAItuProbableCause 이름·번호는 RFC 3877 MIB 원문과 대조하지 않았다)
- 정의: 수립된 연결·세션·link가 끊기거나, 연결은 있는데 사용자 데이터·패킷이 전달되지 않거나 손실·잘못된 경로·잘못된 QoS로 가거나 전송 품질이 나빠진다.
- 포함: 통화·세션 도중 중단, RLF, peer link timer 만료로 끊김, heartbeat 실패로 등록 해제, port가 DOWN에 고착, link·주소 flap, ping 실패, 도달 불가, 한 방향·전부 packet 폐기, 다른 bearer·경로로 흐름, 오류율·재전송 증가, 신호 품질 지표 악화, 무선 송신 신호의 품질·방사 규격 미달, 망 서비스(DHCP·DNS 등)가 응답하지 않음.
- 이웃과 가르기: 처음부터 수립되지 않으면 p.conn.setup. 처리량·지연만 기준에 못 미치고 손실·폐기가 적히지 않으면 p.perf. 처리량 저하와 packet 폐기가 함께 적히면 여기가 주, p.perf는 보조. 보내는 메시지의 내용만 틀리고 끊김·불통이 서술되지 않으면 p.func.wrong. 정책·rate limit이 적용되지 않아 traffic이 더 많이 통과하면 p.func.wrong.

## 출력

`label`은 `p.conn`, `p.conn.setup`, `p.conn.delivery` 가운데 하나다. JSON 객체 하나만 낸다.

```json
{"results": [{"id": "<레코드 id>", "label": "<라벨>", "evidence": "<원문 구절>"}]}
```

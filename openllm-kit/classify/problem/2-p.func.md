# 문제점 축 2단계: `p.func` 기능 오동작 아래 고르기

이 레코드는 1단계에서 `p.func`로 정해졌다. 이제 그 아래 노드 하나를 고른다.

## 할 일

1. 아래 '고르는 규칙'이 있으면 그 순서를 따른다. 없으면 정의·포함 기준이 가장 잘 맞는 노드를 고른다.
2. 더 아래 노드(세분류)가 있으면 거기까지 내려간다. 세분류를 가를 근거가 없으면 그 위 노드에서 멈춘다.
3. 하위를 가를 근거가 없으면 `p.func` 그대로 답한다.
4. 고른 노드의 포함 기준에 맞는 구절을 레코드 원문에서 그대로 복사해 evidence에 넣는다.

완료 기준: 레코드마다 `label`이 아래 목록 안의 값이고, `evidence`가 원문에 글자 그대로 있는 구절이다.

## 하위 노드

### `p.func.fail` 요청·작업 실패 (Request or task failure)

- 표준 대응: IANAItuProbableCause softwareError(163)·configurationOrCustomizationError(506, 유효한 설정 거부); ODC Impact Capability·Usability (IANAItuProbableCause 이름·번호는 RFC 3877 MIB 원문과 대조하지 않았다)
- 정의: 명령·API 요청·background 작업이 오류 응답·예외·거부·timeout 같은 오류 신호를 내며 끝난다.
- 포함: API가 오류·500·traceback 응답, 400이어야 할 곳에 500처럼 오류 형태가 틀림, 관리 명령 실패, agent·event handler 예외로 작업 미수행, 요청 무시로 timeout, 조회 실패, 받은 응답·메시지를 parse하지 못함, handler panic 뒤 오류 응답, 유효한 설정·입력 값을 오류로 거부, 실행 중 설정 파일 parse 오류, 살아 있는 서비스의 개별 작업·요청이 진행 중 상태에 머물러 끝나지 않음.
- 이웃과 가르기: 오류 신호 없이 끝났는데 결과가 틀리거나 효과가 없으면 p.func.wrong. 단말·peer의 접속·세션 수립 실패는 p.conn.setup. 설치·기동 단계의 실패와 기동 중 설정 거부는 p.stage.install·p.stage.startup. panic·segfault 뒤 호출자 응답이나 process 생존이 적히지 않았으면 p.halt. 로그에만 오류가 찍히고 작업은 제대로 끝났으면 p.info.log.

### `p.func.wrong` 잘못된 결과·상태 (Wrong output or state)

- 표준 대응: IANAItuProbableCause corruptData(153)·communicationsProtocolError(504)·configurationOrCustomizationError(506, 설정 미적용); ODC Impact Capability·Standards(규격과 다른 메시지) (IANAItuProbableCause 이름·번호는 RFC 3877 MIB 원문과 대조하지 않았다)
- 정의: 동작이 오류 신호 없이 끝나지만 만들어진 값·출력·송신 메시지·저장 데이터·내부 상태가 기대·규격·운영자 설정과 다르거나, 아무 효과가 없다.
- 포함: 계산·판정 오류, API 응답 필드 누락, 엉뚱한 대상에 동작, 명령이 성공으로 끝나지만 효과 없음, 설정 변경 미적용·일부 적용, option·parameter 무시, 기본값·단위·type 해석 오류, 잘못된·범위 밖 값 수용, 의도하지 않은 생성·삭제, peer에 보내는 메시지의 IE 누락·값 오류·불필요한 송신·미송신·순서 이상, 틀린 forwarding 상태(flow·route·rule 누락), 정책·rate limit 미적용으로 traffic이 더 통과, 삭제 뒤 자원·context 잔류, 구성 요소 사이 상태 불일치, 중복 생성·이중 초기화. 실행 결과 없이 코드를 읽고 틀린 값·동작을 지적한 경우도 여기다(관찰 여부 facet=예상).
- 이웃과 가르기: 오류·예외·거부로 끝나면 p.func.fail. 메시지 이상의 결과로 접속이 거절되거나 끊기거나 traffic이 불통이면 p.conn.*가 주 라벨이고 이 노드는 보조. 화면·로그 문구만 틀리면 p.info.log. 보안 통제 설정(방화벽·권한)이 적용되지 않아 막아야 할 접근이 허용되면 p.sec. 기능 요청이 지금 동작을 설계대로라고 보고 새 동작을 청하면 p.gap.capability.

## 출력

`label`은 `p.func`, `p.func.fail`, `p.func.wrong` 가운데 하나다. JSON 객체 하나만 낸다.

```json
{"results": [{"id": "<레코드 id>", "label": "<라벨>", "evidence": "<원문 구절>"}]}
```
